# Seerr / Jellyfin retention: existing open-source options

Researched 2026-11-17 against project-owned documentation and source. This is research only; nothing was installed, published, or connected to the user's server.

## Recommendation

**Extend Reclaimerr with focused Seerr and Jellyfin integrations.** This is a recommendation based on the current feature surfaces, not a completed integration test. No examined project delivers the entire requested experience unchanged. Reclaimerr already implements the difficult user-facing retention semantics: temporary or permanent protection, automatic approval permissions, Jellyfin accounts, request-aware rules, and deletion management. Its public integration API is a stronger starting point than replacing its cleanup engine. Jellysweep is the nearest runner-up, but its existing Jellyfin plugin does not eliminate several core retention changes.

The proposed additions should make the policy visible at request time, carry the chosen retention period through to the library, show a deletion date in Jellyfin, and allow trusted users to keep/extend media. Existing library items must remain outside the new policy unless deliberately enrolled. Decide whether 60 days starts at request or availability before implementation; source projects do not make those concepts interchangeable.

## Reclaimerr: best overall foundation

- Its protection dialog offers 30, 90, 180, custom days, and permanent protection to ordinary users. It recognizes the `AUTO_APPROVE` permission. [Protection dialog source](https://github.com/jessielw/Reclaimerr/blob/main/frontend/src/lib/components/media/protection-request-dialog.svelte).
- The backend immediately creates approved protection for users with `AUTO_APPROVE`. An omitted duration means permanent; positive days produce a dated protection. This is substantive backend behavior, not just a UI label. [Request endpoint, especially lines 438–507](https://github.com/jessielw/Reclaimerr/blob/main/backend/api/routes/requests.py).
- Jellyfin credentials are a supported login method. A successful identity is resolved or used to create a local account. [Login endpoint](https://github.com/jessielw/Reclaimerr/blob/main/backend/api/routes/auth.py). New local accounts start with `REQUEST` permission, so automatic approval for all present and future friends requires configuration/provisioning or a small default-permission change. [Account creation source, around line 993](https://github.com/jessielw/Reclaimerr/blob/main/backend/services/media_auth.py).
- Rules expose `seerr.requested`, `seerr.days_since_last_requested`, `seerr.last_requested_at`, and requesters. These are enough to build request-aware rules, but a precise 60-day-from-availability contract and cutoff excluding old requests still need deliberate design. [Rule field catalog](https://github.com/jessielw/Reclaimerr/blob/main/docs/reference/rule-fields.md).
- Supports automatic cleanup with review delays, scheduled manual deletion, Leaving Soon collections in Jellyfin, advance requester warnings, and active-playback deferral. Deletion follows service-aware routing through Radarr/Sonarr or the media server. [Deletion flow](https://github.com/jessielw/Reclaimerr/blob/main/docs/usage/deletion-flow.md).
- Its versioned API supports candidate lookup/postpone/protect and temporary or permanent protection by identifiers such as TMDB ID. Repeated protection only widens coverage: permanent wins and dates move later. Whole-title protection covers future copies/seasons, while narrower scopes exist. This makes a thin integration feasible without duplicating cleanup logic. [External API](https://jessielw.github.io/Reclaimerr/reference/api/).
- Favoriting can protect items for all users. Managed favorite protections are reconciled each scan; removing the favorite can later remove that protection. A literal permanent retention request is distinct from remaining protected only while favorited. [Rules](https://github.com/jessielw/Reclaimerr/blob/main/docs/usage/rules.md).
- **Specific gap to harden if the heart becomes a save action:** favorites are cached; failed refreshes can fall back to an old snapshot. Cleanup filters use the snapshot. A last-minute favorite or an unavailable Jellyfin server must not permit deletion based on stale state in the intended product. Add a fresh pre-deletion confirmation / defer-on-unavailability behavior and test the race. [Cache source, around lines 196–219](https://github.com/jessielw/Reclaimerr/blob/main/backend/services/media_favorites_cache.py), [cleanup source](https://github.com/jessielw/Reclaimerr/blob/main/backend/tasks/cleanup.py).
- GitHub identifies its license as GPL-3.0; repository is not archived. Latest release found was **0.6.12, 2026-11-14**. [Repository metadata](https://api.github.com/repos/jessielw/Reclaimerr), [release](https://github.com/jessielw/Reclaimerr/releases/tag/0.6.12).

Remaining product work: request-time retention notice/choices in Seerr; date/retention controls in Jellyfin; trustworthy default approval for future Jellyfin users; new-request-only rollout; clear handling of TV seasons and newly arriving episodes. Neither read source nor docs demonstrated those as a complete ready-made integration.

## Jellysweep: close, but more core behavior changes

Jellysweep already has Jellyfin login, Leaving collections, a user keep-request dashboard, notification options, favorites filtering, and automatic approval permissions. For Jellyfin logins, user permissions are manually managed; OIDC supports an automatic-approval group. Its README says marked items do not pass through eligibility filters again. [README](https://github.com/jon4hz/jellysweep/blob/main/README.md).

Its user keep request accepts no requested duration. Approval sets protection to one library-configured period. Permanent keep is a separate admin operation. Supporting ordinary users choosing custom/permanent retention therefore requires changing the API/state/permission flow. [Engine API](https://github.com/jon4hz/jellysweep/blob/main/internal/engine/api.go).

Content age is derived from Sonarr/Radarr import history. Missing history currently lets an item through the age filter. Seerr supplies requester information rather than determining whether a title belongs to the new retention policy. [Age filter](https://github.com/jon4hz/jellysweep/blob/main/internal/filter/age_filter/filter.go), [requester integration](https://github.com/jon4hz/jellysweep/blob/main/internal/engine/requester.go).

The current code excludes queued items through the database filter before favorites filtering. The cleanup path checks deletion policies, not fresh favorites. The engine explicitly dequeues newly excluded Arr tags and recently played items, but the inspected flow has no corresponding favorite recheck. Thus favoriting during the countdown is not a reliable cancellation mechanism unchanged. [Database filter](https://github.com/jon4hz/jellysweep/blob/main/internal/filter/database_filter/filter.go), [engine](https://github.com/jon4hz/jellysweep/blob/main/internal/engine/engine.go), [cleanup](https://github.com/jon4hz/jellysweep/blob/main/internal/engine/cleanup.go).

Jellysweep is GPL-3.0, not archived, and the latest release found was **v0.16.2, 2026-11-08**. It already has PR lint/tests, race detection, coverage reporting, and a coverage ratchet. [Metadata](https://api.github.com/repos/jon4hz/jellysweep), [release](https://github.com/jon4hz/jellysweep/releases/tag/v0.16.2), [CI workflow](https://github.com/jon4hz/jellysweep/blob/main/.github/workflows/ci.yml).

## Smallest maintainable path

Use Reclaimerr's existing cleanup, protection, authentication, and public API. Add the missing Seerr/Jellyfin experience in focused integrations and upstreamable patches, preserving its license and attribution. Avoid running two independent cleanup engines against the same titles. The boundary between configuration, a companion integration, and an upstream core patch should follow the actual missing behavior, not require a sweeping fork.

For native TV/mobile clients, server metadata/collections/artwork can convey the deadline, and the existing favorite control may become a common save gesture after its semantics and freshness guarantees are implemented. Custom web UI controls cannot be assumed to appear in every native Jellyfin app. Parent research covers the exact Jellyfin plugin/client constraints.

## Integration findings from the parallel parent investigation

Seerr's current movie request form sends media identifiers/type and quality/server/profile/folder/tag options; it does not include retention choices. Its general settings do not supply an existing retention-control UI. A request-time retention choice is therefore an integration/change to implement, not a configuration feature being promised as already present. [Movie request modal](https://github.com/seerr-team/seerr/blob/develop/src/components/RequestModal/MovieRequestModal.tsx), [general settings documentation](https://docs.seerr.dev/using-seerr/settings/general/).

The Jellysweep plugin supports Jellyfin web and apps embedding that web interface, and explicitly excludes native TV clients. Its inspected JavaScript displays a relative deletion-date badge rather than an existing keep-request button. It therefore provides a useful UI example, not a complete solution for the mixed TV/mobile/browser audience. [Plugin repository and compatibility README](https://github.com/jon4hz/jellyfin-plugin-jellysweep).

Suggested product choice for review: the default 60 days begins when requested content becomes available, applies only to new requests, and shows an exact scheduled date. Users can choose longer or forever in Seerr, and any Jellyfin user can save it immediately; TV users can use the favorite control for keeping while phone/browser views offer duration choices. These are proposed product semantics, not verified existing behavior.

## Roku constraint and follow-up source inspection

The user narrowed supported TV clients to the official Jellyfin Roku app. They do not want a separately installed fork or responsibility for maintaining client feature/security updates. They prefer a dedicated Keep button if it can be added without a custom app, and are conditionally willing to use Favorite with explanatory text if a new button requires a custom app. The overall product proposal is still being discussed; no implementation has started.

The inspected Roku title controls are defined in app-owned XML and their handlers in app code. No server-provided custom-action hook was found in the inspected detail/control paths, so a new title-level Keep button should be treated as requiring a client change unless a supported extension path is subsequently established. [Movie detail controls](https://github.com/jellyfin/jellyfin-roku/blob/master/components/movies/MovieDetails.xml), [action handlers](https://github.com/jellyfin/jellyfin-roku/blob/master/source/MainActions.bs).

The existing Favorite action calls the server's MarkFavorite/UnmarkFavorite APIs, so a server-side retention integration can observe it without changing the Roku app. This is Jellyfin favorite state, not a Roku-specific retention command; favoriting from other clients can have the same effect. [Favorite handler](https://github.com/jellyfin/jellyfin-roku/blob/master/source/MainActions.bs#L142).

Stock Roku renders the server-provided Overview for movies, series, and seasons. A short deadline and plain-language instruction can be prepended to that description. Movie overview visibility is configurable and defaults to true; the series preview has only three lines, so the notice must be concise. This is a source-backed display approach, not yet verified on the user's physical Roku. [Movie overview](https://github.com/jellyfin/jellyfin-roku/blob/master/components/movies/MovieDetails.bs#L410), [series overview layout](https://github.com/jellyfin/jellyfin-roku/blob/master/components/tvshows/TVSeriesDetails.xml#L48), [season overview](https://github.com/jellyfin/jellyfin-roku/blob/master/components/tvshows/TVSeasonDetails.bs#L265), [settings](https://github.com/jellyfin/jellyfin-roku/blob/master/settings/settings.json).

Potential copy: "Scheduled for deletion: [date]. Keep forever: mark as Favorite on Roku. For more options, use Keep on your phone or computer." Preserve the underlying synopsis and keep the inserted notice synchronized with retention status. A durable forever decision triggered by Favorite is a proposed addition; stock Reclaimerr's favorite protection only lasts while favorited. Recommend that unfavoriting alone not silently reverse a permanent keep, and handle deliberate removal of protection through explicit retention controls. This semantic choice remains part of the proposal.
